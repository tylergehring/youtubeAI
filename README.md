# Automated Video Generator

A provider-configurable pipeline for educational finance videos, deterministic reels, and
source-led editorial Shorts. Locally supplied transcripts continue to work through the job
pipeline; a separate editorial workflow can retrieve public YouTube captions, draft three
original-topic candidates, and render reviewed short-form video drafts.

External services are workflow-specific: mock providers remain the default for the standard job
pipeline; editorial authoring requires explicit AI-usage approval; YouTube publishing is a
separate command with explicit evidence, rights, audience, channel, and future-schedule gates.
Generated claims are not automatically fact-checked.

## Quick start

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
pip install -e ".[dev]"          # also installs a bundled ffmpeg for tests; Pillow draws reel text

# FFmpeg is required for the render/validate stages. Either have it on PATH or:
$env:FFMPEG_PATH = (python -c "import imageio_ffmpeg; print(imageio_ffmpeg.get_ffmpeg_exe())")

$job = python -m pipeline.jobs create --topic "How TCP works" `
    --transcript C:\transcripts\creator_a.txt --transcript C:\transcripts\creator_b.srt
python -m pipeline.run --job $job
python -m pipeline.jobs status --job $job
```

Output lands in `workspace/jobs/<job_id>/final/` (`video.mp4`, `captions.srt`,
`review_summary.json`); `job_cost.json` is in the job root.

Transcripts are optional (a topic alone works) and are copied into the job, so the originals can
move afterwards. Allowed: `.txt` (blank-line paragraphs; lines like `0:05` are read as timestamps),
`.srt`, `.vtt`; UTF-8, up to 5 MB each, max 10 files (`ingest` in `config/settings.yaml`).

Parsing strips non-speech noise (`[music]`, `>>`, ♪) from the copy it analyses, never from your
original, and splits one-big-block transcripts into sentence chunks. The whole transcript is sent
to the LLM; if it is over `knowledge.max_source_chars` (60,000) the knowledge stage fails instead
of silently cutting text.

Run a single stage (this is exactly what Jenkins does):

```powershell
python -m pipeline.script --job $job            # reuses result if already complete
python -m pipeline.script --job $job --force    # explicitly regenerate
python -m pipeline.run --job $job --from render # re-run a slice
```

Using a real LLM: see "OpenAI LLM provider" in [docs/providers.md](docs/providers.md).

Exit codes: `0` success/reused/skipped, `1` stage failed, `2` usage/config/not-ready.

## Finance facts reels (text-first, portrait 9:16)

A second job format makes short vertical videos: one background image or video you supply, a
dark scrim, and a staged text overlay (title, methodology line, a list of labeled figures, a
closing question, a disclosure). No transcripts or LLM calls are needed; music and narration
are optional local audio files.

```powershell
# One-command demo: no network or API calls. Writes an abstract gradient placeholder background.
python -m pipeline.demo
# -> prints the job, final/video.mp4, a contact sheet of key frames and final/provenance.json

# Your own reel
python -m pipeline.reel --spec examples\finance\editorial_compound.yaml
# -> renders ONE reel, validates it, writes publishing.json, cover.png and a contact sheet
# The example uses the demo background above. Replace it with your own licensed footage.

# Or run individual steps
python -m pipeline.jobs create --format finance_facts --reel-spec examples\finance\retirement_withdrawal.yaml
python -m pipeline.run --job JOB_ID           # finance -> render -> validate -> package
python -m pipeline.preview --job JOB_ID       # key frames + contact sheet in render/preview/
python -m pipeline.preview --job JOB_ID --vscode  # also write a playable VS Code preview
```

VS Code's built-in video viewer cannot play AAC audio. The upload-ready `final/video.mp4`
uses AAC and can be reviewed with VLC or Windows Media Player. With `--vscode`, open
`render/preview/vscode_preview.mp4` instead: its video is copied unchanged and its audio
is converted to MP3 for preview only. Upload the original, not this compatibility copy.

The spec (JSON or YAML) is validated structured data; see
[examples/finance/](examples/finance/) and "Finance reels" in [docs/pipeline.md](docs/pipeline.md)
for every field, the calculation formulas, asset rules and the rendering trade-offs. Figures are
typed in (`manual`) or calculated deterministically (retirement capital, compound growth,
contributions, loans, inflation and doubling time); the demo
numbers are illustrative, not researched or advice. The background must be a file you supply (own
footage, or a clip whose license you hold and record in the spec): nothing is downloaded or
generated by the reel renderer. The separate demo command creates abstract placeholder footage.

For the **editorial** preset, the spec controls headline alignment/size, optional eyebrow text,
ruled versus panel rows, explicit line breaks, local regular/bold fonts, accent colour and pacing.
Custom fonts are copied and hashed into the job. Supplied music is looped and trimmed to the
reel, loudness-processed, faded in/out and ducked under an optional voiceover. Framing can be
adjusted with `background.crop_x`/`crop_y`. Existing specs retain the classic layout.

Every reel includes `final/publishing.json`: a title, description, relevant hashtags, assumptions,
sources and supplied attribution credits derived from the rendered facts. This is a reviewable
publishing draft, **not** an upload, search-ranking prediction or fact-checking service.

Portrait output is configured in the `finance:` block of `config/settings.yaml` (1080x1920 at 30
fps by default); the explainer's landscape `video:` defaults are unchanged.

## YouTube authorization and scheduled upload

YouTube publishing is an explicit command, never part of rendering:

```powershell
pip install -e ".[youtube]"
python -m pipeline.youtube login --client-secrets C:\private\oauth-client.json
python -m pipeline.youtube channel

python -m pipeline.youtube upload --job JOB_ID `
    --channel-id YOUR_CHANNEL_ID `
    --publish-at "2026-10-13T17:00:00-07:00" `
    --made-for-kids no --approve --confirm-rights
```

Create a Google Cloud **Desktop app** OAuth client with YouTube Data API v3 enabled; add your
Google account as a test user while the OAuth app is in Testing. Browser authorization requests
upload and read-only permissions so the destination and schedule can be checked. Tokens and
resumable-upload URLs are stored in the OS credential store (Windows Credential Manager here),
not in the project. Keep the client JSON outside the repository.

Review the reel and confirm all footage/music/font rights before using `--approve --confirm-rights`.
The audience flag is required; use `--contains-synthetic-media yes` when YouTube's altered/synthetic
content disclosure applies. The uploader uses the existing `final/publishing.json` without
generating new claims or uploading a separate custom thumbnail.

Videos are uploaded **private** with a future `publishAt`. The command reads the video back and
checks the channel, audience and schedule before marking the job `uploaded`. That status means
accepted and schedule-verified, **not** already public or guaranteed to pass processing/rights
checks. Once accepted, YouTube handles publication without a local process running at publish time.

The non-secret `youtube_upload.json` receipt lives in the job. Re-run the **same** upload command
after a network interruption: it queries/resumes the existing session or re-verifies the saved
video ID instead of starting a duplicate. If a session is expired or missing, the command stops
for manual reconciliation in YouTube Studio. Do not delete the receipt to bypass this protection.
Past timestamps and changes to an existing receipt's video/metadata/channel/schedule are rejected.

Testing-mode Google OAuth refresh tokens for YouTube expire after seven days; production automation
needs the appropriate production OAuth configuration. Upload quotas and channel limits also apply.
Both single-video and batch upload commands stop on API errors; neither waits automatically
for quota resets or bypasses channel upload limits.
See [YouTube scheduling](https://developers.google.com/youtube/v3/docs/videos#status.publishAt)
and [OAuth testing rules](https://support.google.com/cloud/answer/15549945).

## Daily finance series

[config/campaigns/finance_daily_100.yaml](config/campaigns/finance_daily_100.yaml) defines
100 distinct calculated scenarios across ten finance families, with editorial text,
randomized local backgrounds/music and one daily publication at 5 PM Pacific. These are
clearly disclosed hypothetical calculations, not researched current financial statistics.
Before creating a new batch, set its name, local media libraries, licence statements,
start date and publishing timezone for your own channel.

```powershell
python -m pipeline.batch plan --campaign config\campaigns\finance_daily_100.yaml

# Optional CPU limits for this shell; 0 (the default) leaves thread selection automatic.
$env:VIDGEN__finance__encoder_threads = '4'
$env:VIDGEN__finance__filter_threads = '2'
python -m pipeline.batch run --batch finance_daily_100 --workers 2 --retry-failed
python -m pipeline.batch status --batch finance_daily_100
python -m pipeline.batch export --batch finance_daily_100

# After reviewing the videos, calculated content and media rights:
python -m pipeline.batch upload --batch finance_daily_100 `
    --channel-id YOUR_CHANNEL_ID --made-for-kids no --approve --confirm-rights
```

Planning requires the exact requested number of unique scenarios. The seed makes media
selection reproducible; each background/music pair is distinct, although individual clips
and songs can repeat. Supply enough combinations for the requested count. The plan and
specs are saved under `workspace/batches/finance_daily_100/`; rerunning planning with the
same configuration reuses that calendar. Changed configuration requires a new batch name.
Do not edit the generated specs or job snapshots to change an existing upload.

An IANA timezone such as `America/Los_Angeles` keeps the local publication hour unchanged
across daylight-saving transitions. `publish.csv` records every planned timestamp, selected
asset, job state and verified YouTube link. `export` refreshes it during rendering; uploads
refresh it after each accepted video and on failure.

Batch upload checks that **all** videos have finished rendering and passed QA before sending
the first one. It then uploads sequentially and verifies each remote schedule. On quota,
network or channel errors it stops, retaining receipts and the completed calendar rows.
Resolve the error and rerun the same upload command to resume safely without duplicates.
No local process needs to run at publication time once YouTube accepts the schedule.

## Original, evidence-backed Shorts

The editorial workflow uses a video as a **research lead**, not a script to paraphrase.
The first supported analytical format is fixed-coupon bond price risk:
independent price calculations, original animated visuals, beginner-friendly narration,
measured scene captions, evidence snapshots and a review gate. Graphics use minimal
support text instead of repeating the spoken script; briefs enforce short scenes and copy.

```powershell
pip install -e ".[transcripts]"
python -m pipeline.explainer intake `
    --youtube "https://www.youtube.com/watch?v=5GRH9EeH-DQ" `
    --out workspace\research\bond_risk_source

# Read the transcript, check primary evidence, and review/edit the editorial brief first.
# Uses OPENAI_API_KEY from .env; speech generation is billable.
# Optional: add a user-supplied, licensed vertical video behind the graphics.
python -m pipeline.explainer render `
    --brief examples\explainers\bond_price_risk.yaml `
    --research workspace\research\bond_risk_source `
    --job-id bond_risk_opening_reveal `
    --background-video C:\Users\tyler\Downloads\AiYoutube\video\16405360_1080_1920_25fps.mp4 `
    --approve-evidence
```

Open `workspace/explainers/bond_risk_opening_reveal/final/video.mp4` in a desktop player,
or `final/vscode_preview.mp4` inside VS Code. Output also includes captions, a contact
sheet, narration receipts and publishing copy with source citations and AI-voice disclosure.
The optional background is darkened, looped if necessary, hash-snapshotted in the job, and
its audio is discarded; permission and any required attribution still need human confirmation.
Nothing is uploaded by the rendering command. This explainer workspace is separate from
`pipeline.jobs`; the source-led topic workflow has its own explicit `upload-editorial` command
and cannot schedule anything during generation or rendering.

The demo takes a different angle from the source video's crisis predictions: **a bond can
lose resale value without a default**. Its 4% and 5% yields are hypothetical, not current
quotes. The primary-source excerpts and the independently written brief are in
[examples/explainers/](examples/explainers/).

An LLM/author still chooses the angle, reviews evidence and writes the structured brief.
The software validates that brief and executes the math, graphics, speech and packaging.
It does **not** automatically verify news, certify originality, or guarantee monetization.
New economic topics need appropriate calculations and visuals, not just replacement nouns.
Only original narration is sent to OpenAI; this workflow does not send the source transcript.
Details and limitations: [pipeline documentation](docs/pipeline.md#evidence-backed-editorial-shorts).

## Source-led multi-topic drafts

This workflow takes a public YouTube source as a research lead, fetches available captions,
and asks the configured real LLM for three distinct topics, scripts and visual plans. It does
not copy source footage/audio, search for evidence, or automatically verify financial claims.
The transcript is sent to the configured LLM during authoring; only original narration text is
sent to TTS. Confirm service selection and pricing before each billable step.

```powershell
pip install -e ".[transcripts]"
python -m pipeline.editorial `
    --youtube "https://www.youtube.com/watch?v=5GRH9EeH-DQ" `
    --batch-id bond_source_topics `
    --approve-ai-usage

# After reviewing the three scripts/visual plans, render one topic at a time.
python -m pipeline.editorial `
    --batch-id bond_source_topics `
    --topic topic-1 `
    --approve-ai-usage `
    --background-video "C:\path\to\licensed-background.mp4" `
    --background-license "State the verified permission or licence"
```

Configure a real LLM and TTS provider first. A successful authoring batch makes seven structured
LLM requests (one topic shortlist, three scripts, three visual plans); narration uses one TTS
request per script scene. The visual plan is rendered deterministically with Pillow/FFmpeg—no
image-generation provider is used. The cost ledger records configured estimates, not an invoice.
Drafts, hashed assets, captions, previews, technical QA and publishing metadata are stored under
`workspace/editorial_batches/<batch-id>/<topic-id>/`. The renderer centers rectangle labels inside
their boxes and uses a translucent graphics layer over supplied backgrounds. Keep each rectangle
within the frame's safe margin. Supplying background/music requires an explicit permission/licence
note; asset hashes identify bytes but do not establish ownership.

Every render stops at `awaiting_review`. Inspect the encoded video and listen to the narration,
independently verify every financial claim against appropriate evidence, review originality and
rights, and edit `final/publishing.json` to add verified citations as needed. The five-word
overlap check is only a copying heuristic, not legal clearance or a monetization guarantee.

Only after review, one topic can be scheduled through the existing resumable YouTube protocol:

```powershell
python -m pipeline.youtube upload-editorial `
    --batch-id bond_source_topics `
    --topic topic-1 `
    --channel-id UC_REPLACE_WITH_YOUR_CHANNEL_ID `
    --publish-at "REPLACE_WITH_FUTURE_ISO_8601_TIME_AND_OFFSET" `
    --made-for-kids no `
    --contains-synthetic-media yes `
    --approve `
    --evidence-reviewed `
    --confirm-rights
```

Choose the audience and synthetic-media declarations according to the content and current
YouTube requirements; the tool does not decide them. Scheduling is one video per explicit
command. YouTube acceptance is verified by channel, privacy and future schedule, but does not
guarantee processing, publication, rights clearance or monetization. No live service calls or
uploads are performed just by creating or rendering a draft.
